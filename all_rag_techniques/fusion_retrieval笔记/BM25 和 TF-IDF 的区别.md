## 1. TF-IDF 是啥

**全称：Term Frequency – Inverse Document Frequency**
它是一个统计方法，用来衡量某个词在某篇文档里有多重要。

* **TF（词频）**：某个词在这篇文档里出现了多少次。
* **IDF（逆文档频率）**：这个词在所有文档里是不是常见？越少见的词权重越高。

👉 简单说：**TF-IDF = 词在这篇文档里出现得多 × 在所有文档里出现得少 → 重要！**

**例子：**
假设有 3 篇文档：

1. `"Redis is fast"`
2. `"Redis is memory database"`
3. `"Database is important"`

查询：`Redis`

* `Redis` 在文档 1 出现 1 次，在文档 2 出现 1 次，在文档 3 没有出现。
* 但 `is` 出现在所有文档里 → 权重很低（因为大家都有，就不算特别重要）。
* 所以 TF-IDF 会觉得 `Redis` 是关键字，`is` 就不重要。

---

## 2. BM25 是啥

**全称：Best Matching 25**
它是 TF-IDF 的改进版，属于概率模型里的排序函数。

它考虑了两个 TF-IDF 没有的点：

1. **文档长度归一化**：

   * 长文档天然有更多词汇，所以 TF-IDF 容易高估长文档的分数。
   * BM25 会“惩罚”长文档，避免长文档因为凑巧包含很多词就排第一。

2. **词频饱和效应**：

   * 在 TF-IDF 里，词出现越多次分数越高。
   * 但在现实里，一个词出现 10 次和 100 次，其实相关性差别没那么大。
   * BM25 加了一个“饱和函数”，词频增加时，分数提升会逐渐变小。

👉 简单说：

* **TF-IDF**：词越多分数越高，没考虑文档长短。
* **BM25**：词多到一定程度就够了（不会无限加分），还会考虑文档长度，让结果更公平。

---

## 3. 举个对比例子

假设有两篇文档：

* 文档 A: `"Redis Redis Redis Redis Redis Redis Redis Redis Redis Redis"`（10 次 Redis）
* 文档 B: `"Redis is fast"`（1 次 Redis）

查询：`Redis`

* **TF-IDF**

  * 会认为文档 A 超级相关（因为 Redis 出现 10 次）。
  * 文档 B 相关性比较低。

* **BM25**

  * 会觉得文档 A 和文档 B **差不多相关**。
  * 因为在文档 A 里，`Redis` 出现 10 次，其实已经饱和了，再多也没那么大意义。
  * 而文档 B 虽然只出现 1 次，但也足够说明它和 `Redis` 有关。

---

## 4. 一句话总结

* **TF-IDF**：算“这个词在这篇文档里多重要”。
* **BM25**：在 TF-IDF 的基础上，加了“词频饱和”和“文档长度修正”，更贴近真实搜索的相关性。
